# CK Quant 2026.8.14

## 长期运行性能优化

- 修复 WebUI 定时刷新时反复分页读取全部历史交易与订单的问题。
- 历史交易列表改为按变化刷新，并使用不包含订单明细的轻量响应。
- `/profit` 与 `/profit_all` 使用紧凑字段和增量缓存，避免重复构造全部历史交易 ORM 对象。
- 新平仓统计只聚合水位之后的新增交易和订单，不再随历史订单数量线性重复扫描。
- 修复轻量历史响应仍会隐式加载订单关系的问题。
- 为长期运行数据库增加交易与订单复合索引；已有 SQLite 数据库会在启动时自动补齐索引。
- 优化实盘钱包同步中缺失杠杆时的查询，消除按持仓逐笔查询数据库的情况。

## 延迟诊断

- 主循环、开仓、平仓和钱包同步增加分阶段耗时日志。
- 当操作超过阈值时，日志会区分市场数据、策略计算、数据库提交、交易所下单及钱包同步耗时，便于识别交易所网络延迟与本地数据库延迟。

## 压力验证

- 30,011 笔已平仓交易、90,484 条订单的模拟数据中：旧全量历史读取约 1.62 秒并序列化 96.3 MiB；新版最近 500 笔轻量读取约 0.011 秒、约 696 KiB。
- 紧凑统计首次快照约 0.061 秒，缓存水位查询接近 0 秒。
- 重点后端、数据库、钱包、交易热路径和 API 回归测试通过。
- WebUI、Docker 隐私检查和生产镜像构建通过。
