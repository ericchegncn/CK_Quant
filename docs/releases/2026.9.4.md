# CK Quant 2026.9.4

主循环提速（修复长时间运行后的「卡死」观感）（**后端改动，前端未改，本版不含 APK**）。

## 背景

云端趋势盘 33 持仓时，主循环单轮墙钟 9.2~9.6 秒，其中出场阶段与行情预取占了绝大部分。
逐相位计时定位到**三个各自独立的重复请求源**，都会在每轮对每个持仓重复发同一份深度数据。

## 三个请求源与改法

### 1. 出场行情预取（prefetch）：两次合约行情调用 → 一次

- 合约上 `get_tickers` 实际是 `fetch_tickers` + `fetch_bids_asks` **两次**请求，外加全市场
  `deep_merge`；而 prefetch 只用买一/卖一。
- 改为**只调一次 `fetch_bids_asks`**，在本地合成 `order_book_top=1` 的顶档盘口；
  取不到时回退原 `get_tickers` 路径（行为不变）。
- 同时新增 `pairs`/`tickers`/`rates` 三段细分计时（>0.5s 才记日志）与顶档缓存命中计数，
  用于定位剩余开销；修复前一版诊断计数在写入时被清零、导致恒打印 0 的错误。

**机理（实测）**：ccxt 在 freqtrade 默认的 `enableRateLimit=True` 下会把 prefetch 每轮的
两次合约行情调用配速到 **1367ms**；同一镜像关掉限速只要 **259ms**。
⇒ 单轮墙钟本质上就是「**每轮请求条数 × 配速**」，削减请求数即等比例提速。

### 2. 止损穿越判定（`exit.sl_check`）：每止损单每轮一次 L2 → 0 请求

- dry-run 的止损穿越判定 `_dry_is_price_crossed` 只读 `bids[0]`/`asks[0]`，但
  `check_dry_limit_order_filled` 原先为此**对每个止损单、每轮**发一次 `depth=20` 的
  `fetch_l2_order_book`（33 持仓实测 `exit.sl_check` ≈ **3.17s/轮**）。
- 现在优先复用本轮批量行情已取回的顶档盘口（命中 = **0 请求**）；
  未命中/TTL 过期回退原 `depth=20` 请求；真被穿越（罕见）时补一次真实深度，
  保证 `get_dry_market_fill_price` 的成交价插值保真度不变。
- 限价单分支同理：`_dry_is_price_crossed` 未显式传入盘口时先查本轮缓存（与 `depth=1` 等价，
  命中 0 请求），未命中仍走原 `fetch_l2_order_book(pair, 1)`——原「每单每轮一次 depth-1 请求」
  （33 持仓 ≈ **3.5s/轮**）请求归零。
- 全部为**加性改动**：旧路径逐行保留为回退，diff 删除行 = 0。

### 3. `handle_trade` 的强制实时刷新：每笔每轮一次 L2 → 读本轮缓存

- 定位：`handle_trade` 每笔每轮固定 **~98ms × 33 = 3.24s**，源于
  `get_rate(..., refresh=(refresh_rate or _use_order_book))`——合约上 `use_order_book`
  必须为 `true`（`validate_pricing` 强制），该表达式**恒为 True**，于是绕过本轮预取缓存，
  每笔各发一次 depth L2 请求。
- 改为按调用方要求 `refresh=refresh_rate`：`exit_positions` 传 `False` 时读本轮缓存，
  其他调用方传 `True`，行为不变；缓存未命中时 `get_rate` 仍回退单笔实时请求
  （不会用到过期/缺失价格）。
- 同步修正导致该写法的错误注释前提，并删除因此失效的 `_use_order_book` 局部变量。

## 实测（同一云机，33 持仓，逐相位计时）

| 项目 | 改前 | 改后 |
|---|---|---|
| prefetch | 1.75s | **0.10s** |
| `exit.sl_check` | 3.2s | **0.4~1.5s** |
| `handle_trade` | 3.5s | **0.66~1.10s** |
| **单轮合计** | 9.2~9.6s | **2.5~3.2s（≈3.4×）** |

- 速率限制器实测：同容器同两次调用 `enableRateLimit=True` **1367ms** vs `False` **259ms**。
- 顶档盘口复用后 `exit.sl_check` 的中间观测值为 3.2s → ~2.0s（限价单分支归零）。

## 适用面（重要）

- **仅 dry-run**：三个提交中的行情预取复用与止损穿越缓存命中改动，**影响面仅 dry-run**；
  实盘走 2026.9.2 的挂单快照路径，一行未动。
- **dry-run 与实盘共用**：`perf(exit)` 去掉强制实时刷新这一项位于共用出场路径——
  `exit_positions` 传 `False` 时读本轮缓存（实盘与模拟盘都能受益），其他调用方传 `True`
  行为不变。
- 无新增请求、不调节流；缓存未命中一律回退原请求，成交价与状态处理语义不变。
- 新增测试 `tests/exchange/test_dry_top_of_book_cache.py`：命中 = 0 请求 / 穿越补深度 /
  未命中回退（反证）/ TTL 过期 / 非 dry-run 不缓存。

## 验收口径

日志中这三项同时下降即为生效：`prefetch` ≈0.1s、`exit.sl_check` 0.4~1.5s、
`handle_trade` 0.66~1.10s，单轮合计回落到 2.5~3.2s。
新增的 `pairs`/`tickers`/`rates` 细分计时只在单项 >0.5s 时打印，平时不会刷日志。
